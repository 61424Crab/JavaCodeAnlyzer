# ソースコードレビュー観点

## A. 設計・仕様

- [ ] 設計、仕様、受入条件どおりに実装されているか。
- [ ] 今回の変更要求をすべて実装しているか。
- [ ] 業務ルールや異常系の実装漏れがないか。
- [ ] 仕様外の動作を追加していないか。
- [ ] 公開インターフェースに未説明の変更がないか。
- [ ] 今回の要件と無関係な変更がないか。
- [ ] デフォルト値、デフォルト動作、処理結果が仕様どおりか。

## B. 処理ロジック

- [ ] 処理順序が正しいか。
- [ ] 条件分岐が網羅され、条件の重複や矛盾がないか。
- [ ] 正常系、異常系、境界条件を正しく処理しているか。
- [ ] 到達不能な分岐、または実行漏れの分岐がないか。
- [ ] ループの開始、終了、脱出条件が正しいか。
- [ ] 再実行で重複データや不要な副作用が発生しないか。
- [ ] 必要な冪等性が確保されているか。
- [ ] 部分成功、部分失敗で不整合が発生しないか。
- [ ] 状態変更の順序が正しいか。
- [ ] 失敗時に中間状態が残らないか。
- [ ] 共有オブジェクトやグローバル状態を誤って変更していないか。

## C. 入出力・更新内容

- [ ] 入力値の型、形式、範囲を検証しているか。
- [ ] `None`、空文字、空コレクション、0、負数を正しく扱っているか。
- [ ] 最大値、最小値、長大文字列、特殊文字を正しく扱っているか。
- [ ] 日付、時刻、タイムゾーンを正しく扱っているか。
- [ ] 小数精度と丸め方法が業務要件に合っているか。
- [ ] 戻り値、エラーコード、ステータスが一貫しているか。
- [ ] 更新対象と更新内容が正しいか。
- [ ] 更新対象外のデータを上書きしていないか。
- [ ] 重複入力、重複リクエストが安全に処理されるか。
- [ ] 出力に不要な情報や機密情報が含まれていないか。

## D. 例外・エラー・ログ

- [ ] 適切な例外型を捕捉しているか。
- [ ] 広すぎる例外捕捉がないか。
- [ ] 空の `except` や例外の握りつぶしがないか。
- [ ] 例外発生後に誤って処理を継続していないか。
- [ ] 失敗時に成功ステータスを返していないか。
- [ ] 元の例外情報とスタックトレースを保持しているか。
- [ ] 回復可能な例外と回復不能な例外を区別しているか。
- [ ] 例外時にもクリーンアップ処理が実行されるか。
- [ ] 重要な開始、終了、失敗をログへ記録しているか。
- [ ] ログレベル、内容、業務識別子が適切か。
- [ ] パスワード、Token、個人情報、接続情報をログへ出力していないか。
- [ ] 高頻度処理で過剰なログを出力していないか。

## E. セキュリティ

- [ ] ユーザー入力を検証しているか。
- [ ] SQL でパラメータバインドを使用しているか。
- [ ] コマンドインジェクションがないか。
- [ ] パストラバーサルや任意ファイルアクセスがないか。
- [ ] SSRF、XSS、CSRF のリスクがないか。
- [ ] 認証回避や権限外アクセスがないか。
- [ ] パスワード、秘密鍵、Token、接続情報をハードコードしていないか。
- [ ] 認証情報に安全でない乱数を使用していないか。
- [ ] 信頼できないデータを安全でない方法でデシリアライズしていないか。
- [ ] エラーメッセージで内部実装を公開していないか。
- [ ] アップロードファイルの種類、サイズ、名称、保存先を制御しているか。
- [ ] 外部ライブラリを安全に使用しているか。

## F. 可読性・保守性

- [ ] プロジェクトのコーディング規約に準拠しているか。
- [ ] 命名が意図を正確に表しているか。
- [ ] 関数、クラス、モジュールの責務が明確か。
- [ ] 長すぎる関数、深すぎるネスト、重複コードがないか。
- [ ] マジックナンバー、マジック文字列を定数化すべきか。
- [ ] コメントが理由を説明し、実装と一致しているか。
- [ ] 隠れた副作用がないか。
- [ ] 設定値がコードから分離されているか。
- [ ] 既存のプロジェクト構造に従っているか。
- [ ] 無意味な抽象化や過剰設計がないか。
- [ ] 強い結合によりテストが困難になっていないか。
- [ ] AI 生成による冗長なラッパーや不統一なスタイルがないか。

## G. 性能・リソース

- [ ] 不要な多重ループや重複計算がないか。
- [ ] ループ内で DB や外部サービスを繰り返し呼んでいないか。
- [ ] 大量データを一括で読み込んでいないか。
- [ ] ページング、ストリーミング、バッチ処理が適切か。
- [ ] 無限リトライ、無制限キャッシュ、無制限キューがないか。
- [ ] 必要なタイムアウトを設定しているか。
- [ ] ファイル、接続、カーソル、レスポンスを閉じているか。
- [ ] ロックを長時間保持していないか。
- [ ] N+1 クエリがないか。
- [ ] 性能判断にデータ量、実行計画、測定結果の根拠があるか。

# 単体テスト項目レビュー観点

## H. テスト網羅性

- [ ] テストケースが設計、仕様を網羅しているか。
- [ ] 正常系を含んでいるか。
- [ ] 異常系を含んでいるか。
- [ ] 境界値を含んでいるか。
- [ ] 主要な条件分岐を含んでいるか。
- [ ] 不正入力を含んでいるか。
- [ ] 外部サービスのタイムアウトや失敗を含んでいるか。
- [ ] リトライ、再実行を含んでいるか。
- [ ] 必要な回帰テストがあるか。
- [ ] 新規・変更ロジックに対応するテストがあるか。

## I. テスト条件・期待値

- [ ] 入力値が妥当か。
- [ ] 前提条件が妥当か。
- [ ] 期待値が妥当か。
- [ ] テスト名が条件と期待結果を表しているか。
- [ ] アサーションが重要な結果を確認しているか。
- [ ] 「例外が発生しないこと」だけを確認していないか。
- [ ] 戻り値と副作用の両方を確認しているか。
- [ ] 例外型とエラー内容を確認しているか。
- [ ] テストデータが実際の業務条件に合っているか。
- [ ] 日付、タイムゾーン、小数精度の条件が正しいか。

## J. Mock・テスト独立性

- [ ] Mock が実際のインターフェースと一致しているか。
- [ ] Mock の戻り値と例外が現実的か。
- [ ] Mock を過剰に使用していないか。
- [ ] 正しい呼出箇所を patch しているか。
- [ ] テストが実行順に依存していないか。
- [ ] テストが現在時刻に依存していないか。
- [ ] 乱数、UUID、時刻を制御できるか。
- [ ] テストデータと一時ファイルが分離されているか。
- [ ] 外部ネットワークや不安定なサービスに依存していないか。
- [ ] テスト後に状態をクリーンアップしているか。

## K. DB テスト

- [ ] Commit と Rollback を確認しているか。
- [ ] Unique、FK、CHECK 制約を確認しているか。
- [ ] 並行更新と更新消失を確認しているか。
- [ ] リトライと冪等性を確認しているか。
- [ ] テストデータをテスト後に削除しているか。
- [ ] PostgreSQL 固有の動作で確認しているか。
- [ ] SQLite の成功だけで PostgreSQL 検証済みとしていないか。
- [ ] DB マイグレーションに検証手順があるか。

# 技術固有レビュー観点

## L. Python

### バージョン・依存関係

- [ ] Python バージョンが明確か。
- [ ] 構文と標準ライブラリが対象バージョンと互換か。
- [ ] 外部ライブラリ、クラス、メソッド、引数が実在するか。
- [ ] 依存バージョンが現在の使用方法をサポートするか。
- [ ] 非推奨 API を使用していないか。
- [ ] 同期・非同期ライブラリを誤って混用していないか。
- [ ] 不要な依存関係を追加していないか。

### 型・データ

- [ ] 型ヒントと実際の値が一致するか。
- [ ] 戻り値型がすべての分岐をカバーするか。
- [ ] `Optional` を正しく処理しているか。
- [ ] 可変デフォルト引数を使用していないか。
- [ ] `Any` を乱用していないか。
- [ ] `Decimal`、`float`、`datetime` の変換が正しいか。
- [ ] bool、int、Enum を正しく扱っているか。
- [ ] シリアライズ前後で型が維持されるか。

### Python 特有の問題

- [ ] `is` と `==` を正しく使用しているか。
- [ ] shallow copy と deep copy の選択が正しいか。
- [ ] closure の late binding がないか。
- [ ] iteration 中に collection を変更していないか。
- [ ] generator を再度消費していないか。
- [ ] truthy/falsy 判定が有効な `0`、`False`、空 collection を隠していないか。
- [ ] float を直接比較していないか。
- [ ] aware / naive datetime を混用していないか。
- [ ] ファイル encoding が明確か。
- [ ] current working directory に依存していないか。
- [ ] import 時の副作用や circular import がないか。

### 非同期・リソース・セキュリティ

- [ ] `async def` 内に blocking I/O がないか。
- [ ] coroutine を正しく `await` しているか。
- [ ] 未回収 task がないか。
- [ ] cancel と timeout を処理しているか。
- [ ] DB Session や connection を task 間で誤共有していないか。
- [ ] ファイル、response、connection、cursor を閉じているか。
- [ ] `eval`、`exec`、信頼できない `pickle` を使用していないか。
- [ ] `subprocess(shell=True)` が安全か。
- [ ] YAML を safe load しているか。
- [ ] JWT の署名、algorithm、expiry を検証しているか。
- [ ] secure Token に `secrets` を使用しているか。

## M. PostgreSQL

### SQL 正確性

- [ ] table、column、alias が正しいか。
- [ ] JOIN 条件が完全か。
- [ ] Cartesian product がないか。
- [ ] `NULL` を正しく扱っているか。
- [ ] `NOT IN` と `NULL` を誤用していないか。
- [ ] aggregate と `GROUP BY` が一致するか。
- [ ] sort が安定し、paging に決定的な順序があるか。
- [ ] 日時範囲の境界が正しいか。
- [ ] `ON CONFLICT` の対象が正しいか。
- [ ] `UPDATE`、`DELETE` に正しい WHERE 条件があるか。
- [ ] `RETURNING` を正しく扱っているか。

### パラメータ・トランザクション・並行処理

- [ ] parameterized query を使用しているか。
- [ ] user input を直接連結していないか。
- [ ] dynamic table、column、sort field を whitelist で制御しているか。
- [ ] `LIKE` の wildcard と escape が正しいか。
- [ ] 複数の write が同一 transaction 内か。
- [ ] Commit、Rollback の境界が正しいか。
- [ ] 例外後の transaction state を処理しているか。
- [ ] partial commit がないか。
- [ ] transaction 内で長時間の外部サービスを呼んでいないか。
- [ ] isolation level が要件に合っているか。
- [ ] read-then-update race がないか。
- [ ] `SELECT ... FOR UPDATE` が必要か。
- [ ] optimistic lock、UPSERT、deadlock risk を適切に扱っているか。
- [ ] long transaction が Vacuum に影響しないか。
- [ ] queue 処理に `SKIP LOCKED` が適切か。

### データ型・制約・インデックス・マイグレーション

- [ ] 金額に適切な `numeric` を使用しているか。
- [ ] timestamp と timezone の方針が明確か。
- [ ] `varchar(n)`、`text`、ID、JSON/JSONB の選択が妥当か。
- [ ] `numeric` の precision と scale が正しいか。
- [ ] empty string と `NULL` の規則があるか。
- [ ] PK、FK、Unique、NOT NULL、CHECK が妥当か。
- [ ] 論理削除後の unique が要件に合っているか。
- [ ] WHERE、JOIN、ORDER BY の列に index が必要か。
- [ ] composite、partial、expression index が妥当か。
- [ ] 大量 OFFSET を Keyset Pagination に変更すべきか。
- [ ] `EXPLAIN (ANALYZE, BUFFERS)` が必要か。
- [ ] 大規模 table migration が長時間 lock しないか。
- [ ] NOT NULL column 追加で既存データを考慮しているか。
- [ ] `CREATE INDEX CONCURRENTLY` が必要か。
- [ ] backfill を分割しているか。
- [ ] migration failure から復旧できるか。
- [ ] 新旧バージョンが互換か。

## N. Python・PostgreSQL 連携

- [ ] Python type と PostgreSQL type が一致するか。
- [ ] `None` と SQL `NULL` の変換が正しいか。
- [ ] `Decimal` を `float` に誤変換していないか。
- [ ] `datetime` に timezone があるか。
- [ ] UUID、JSONB、array、Enum の mapping が正しいか。
- [ ] connection pool size が妥当か。
- [ ] transaction の責務レイヤーが正しいか。
- [ ] 例外後に Rollback しているか。
- [ ] result を大量に一括読込していないか。
- [ ] bulk write が実際に bulk 実行されるか。
- [ ] ORM が N+1 を発生させていないか。
- [ ] ORM Cascade が意図せず削除しないか。
- [ ] Autocommit が要件に合っているか。
- [ ] DB exception を適切な業務 error に変換しているか。
- [ ] unique conflict を正しく処理しているか。
- [ ] retry を retryable error に限定しているか。

## O. AI 生成コード

- [ ] 架空の library、class、function、argument、config がないか。
- [ ] API と依存バージョンが一致しているか。
- [ ] 他 DB の SQL 方言が混在していないか。
- [ ] sync API を async API として使用していないか。
- [ ] 架空の戻り値 field、exception type がないか。
- [ ] demo、sample 環境限定の実装でないか。
- [ ] sample password、placeholder、test URL が残っていないか。
- [ ] コメントと実際の動作が一致しているか。
- [ ] 無意味な abstraction、冗長な wrapper がないか。
- [ ] standard library や framework 機能を重複実装していないか。
- [ ] test、Mock が実行可能か。
- [ ] table、index、Extension の存在を誤って仮定していないか。
- [ ] 根拠なく thread-safe、transaction-safe、高性能と説明していないか。
- [ ] file 間で命名、type、error handling が一貫しているか。

## レビュー指摘記録テンプレート

```markdown
### [重大度] 指摘タイトル

- ファイル：
- 箇所：
- レビュー観点：
- 問題：
- 発生条件：
- 影響：
- 判断根拠：
- 修正案：
- 状態：確定 / 要確認
```

重大度の目安：

- `BLOCKER`：merge、release 前に必ず修正する。
- `HIGH`：機能、安全性、データに重大な影響がある。
- `MEDIUM`：信頼性、保守性、test quality に影響する。
- `LOW`：軽微な改善。
- `INFO`：参考提案。
